# 3D Reconstruction Diffusion 文档整理设计

状态：已获用户确认，待执行

日期：2026-08-24

## 目标

把当前仓库中分散的项目说明、实验设计、过程日志、结果说明和审计资料整理成
一个可导航、可追溯的文档体系。整理只改变入口、索引和说明，不删除历史内容，
也不把旧实验结果改写成新 CVA02 的结论。

## 文档层级

### 1. 项目总入口

根目录 `README.md` 说明项目要解决的问题、研究演进、当前主线、分支/工作树、
环境与数据位置、如何运行、结果在哪里以及下一步是什么。

### 2. 文档索引

`docs/README.md` 按四类索引所有资料：

- 当前实验：CVA02 设计、计划、协议和状态；
- 历史实验：local/global、camera iteration、stitching 等；
- 数据与工具：ScanNet/FastVGGT、下载、评测和可视化；
- 过程记录：日志、数值结果和审计报告。

每个条目注明用途、状态和是否允许作为当前结论依据。

### 3. 当前 CVA02 主线

在 `docs/` 下增加当前实验入口和状态说明，明确：

- CVA02 继承 015 的哪些代码和哪些语义不再继承；
- calibration-first、development evaluation 和 decision gate 的顺序；
- ScanNet 完整性门控、H20 路径和输出路径；
- Person A/B/C 的任务边界；
- 结论资格与“不可识别”条件。

现有详细设计和实施计划继续保留为规范正文，由入口文档链接过去。

### 4. 历史与辅助资料

不移动、不删除 `doc/`、`log/`、历史 `README` 和结果说明，只在入口中标记：

- 历史设计/实现计划；
- 已完成实验及其结论范围；
- 仅供审计或复现的资料；
- 不得直接替代 CVA02 新鲜输入的旧结果。

`cva02_local`、`velocity_repo_audit` 和 `FastVGGT_audit` 标记为辅助副本或审计
工作区，主开发路径固定为 `cva02_dev`。

## 交叉链接规则

- 新入口使用仓库相对路径；
- H20、数据集、权重和输出使用代码块中的绝对路径；
- 历史文档不改写实验结论；
- 当前状态只在主入口和 CVA02 状态页维护，避免多个“当前进度”来源；
- 每个实验文档开头标明 `状态`、`用途` 和 `是否可作为当前结论依据`。

## 验收标准

- 新用户只读根 README 和 `docs/README.md` 即能找到当前主线；
- 能从 CVA02 入口追溯到设计、计划、代码、日志和输出位置；
- 能明确区分历史结论、当前待验证假设和不可用的旧结果；
- 不改变现有代码、数据、权重和历史结果文件；
- 所有新增文档无 `TODO`、`TBD` 或未解释的占位符。
